# Non-Technical Approval System

## Problem
Users shouldn't need to review raw Python/Bash code to approve automations. Most users don't read code and won't understand technical implementation details.

## Solution
Present approvals in plain English with 3 levels of detail:

### Level 1: Initial Notification (Always Shown)
User sees a pattern detection message:
```
📧 **Email pattern detected**

You send similar emails with subject: "Weekly Report" (12 times recently).

Would you like me to create a template to save time writing these?
```

### Level 2: Automation Proposal (If User Interested)
When LLM generates code, user sees NON-TECHNICAL approval:
```
🤖 **New Automation Available**

**Quick Reply: Weekly Reports**

Automatically create a draft email template with your standard 
weekly report format, pre-filled with common sections.

**Why this helps:**
You write similar emails 12× per month (saves ~2 hours/month)

**What changes:**
A "weekly-report" command will be available to generate drafts.
You still review and edit before sending.

**Safety:** 🟢 Low risk

**Actions:**
✅ Approve - Deploy this automation
ℹ️ Details - See technical specs (optional)
❌ Decline - Not interested

This automation was generated by AI and has been safety-validated.
```

### Level 3: Technical Details (Optional)
Only shown if user clicks "Details":
```
🔧 **Technical Details**

**Script:** weekly_report_template
**Language:** Python

**What it does (step-by-step):**
1. Import required tools
2. Load email template configuration
3. Read standard sections from saved file
4. Create draft email with pre-filled content
5. Open in default email client

**Files created:**
• ~/.openclaw/workspace/scripts/weekly_report_template

**Permissions:**
• Read/write access to workspace directory
• No elevated (sudo) access required

**Code review:**
The full source code is available for inspection.
Run: hobbes show-code weekly_report_template
```

## Implementation

### Pattern Detection (Step 1)
File: `auto_optimizer.py`, function `_generate_pattern_message()`
- Returns simple, non-technical pattern notification
- No code, no implementation details
- Just: "I noticed X, want help?"

### Approval Generation (Step 2)
File: `non_technical_approval.py`, function `format_approval_message()`
- Takes pattern + generated_code
- Formats NON-TECHNICAL approval
- Uses: user_title, user_explanation, why_recommended, what_changes, risk_level
- **Never includes raw code**

### Technical Details (Step 3)
File: `non_technical_approval.py`, function `format_technical_details()`
- Only shown if user requests it
- Still avoids raw code
- Shows: high-level steps, files created, permissions needed

## User Flow

```
Pattern Detected
    ↓
Simple Notification ("I noticed you do X often")
    ↓
User: "Yes, help me"
    ↓
LLM Generates Code (behind the scenes)
    ↓
Non-Technical Approval Presented
    ↓
User Sees: What / Why / Changes / Risk
    ↓
User: "Approve" or "Details" or "Decline"
    ↓
If "Details" → Show technical overview (still no raw code)
    ↓
If "Approve" → Deploy automation
    ↓
Success Message (also non-technical)
```

## Code Never Shown
Users **never** see in notifications:
- Raw Python/Bash code
- Function definitions
- API calls
- Import statements
- Variable names
- Technical jargon

## What Users See
Users **always** see:
- Plain English description
- Why it's recommended (time savings, frequency)
- What will be different (behavior changes)
- Risk level (low/medium/high)
- Clear action buttons

## Benefits
1. **Accessibility:** Non-technical users can approve automations
2. **Safety:** Users understand what they're approving
3. **Trust:** Clear explanations build confidence
4. **Speed:** No code review required for simple automations
5. **Transparency:** Technical details available on request

## Example Comparison

### ❌ Technical (Old Way)
```
Proposal: command_retry_curl
Language: Python
Confidence: 85%

Code:
#!/usr/bin/env python3
import subprocess
import time

def retry_curl(url, max_retries=3):
    for i in range(max_retries):
        result = subprocess.run(['curl', url], capture_output=True)
        if result.returncode == 0:
            return result.stdout
        time.sleep(2)
    return None

Approve? (y/n)
```

### ✅ Non-Technical (New Way)
```
🤖 **Auto-Retry Failed Downloads**

Automatically retry curl downloads up to 3 times when they fail.

**Why this helps:**
You manually retry curl 15× per week (saves ~5 min/week)

**What changes:**
curl will retry automatically on failure - no changes to your workflow

**Safety:** 🟢 Low risk

✅ Approve  ℹ️ Details  ❌ Decline
```
